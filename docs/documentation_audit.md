# Documentation audit — 2026-09-19

## Scope and assessment

Reviewed the documentation against repository state `de097eb` (PDO 0.2.0), especially `9758abe` (desktop/release pipeline), `b21c80c` (tray Open), `29ec2d4` and `f01b63f` (CI corrections), `94a0aa0` (guided workflow, bulk recovery, CSV formats), and `de097eb` (Git workflow rules).

README and Getting Started already described much of the new GUI. The main drift was in the CLI contract and older implementation workflows. Several apparent documentation problems are real CLI limitations; they are documented here without changing application behavior.

Inspected README, all Markdown under `docs/`, `AGENTS.md`, `.agents/rules/rules.md`, all six `.agents/workflows/` files, and the `.gemini/rules.md` redirect. Checked claims against CLI/core/daemon/desktop code, tests, configuration, setup/build scripts, Dockerfiles, packaging metadata, and both CI workflows. External release availability and live provider model availability were not verified; documented model names are code defaults.

## Application follow-ups still open

These are code issues discovered while checking documentation. This audit changes documentation only.

1. **C01 — High: propagate custom configuration through the CLI.** `pdo --config alternate.toml daemon start` calls `load_config()` without that path; pipeline commands similarly call `send_command()` without the selected config. `logs` also ignores it. A test should use distinct default/custom directories and verify both daemon startup and subsequent client routing. Current workaround: consistent `PDO_DATA_DIR`/`PDO_LOG_DIR`, with provider settings in the daemon's actual config file.
2. **C02 — High: make failure exit codes reliable.** For example, an `optimize` response with `success=False` can exit 0. `OutputManager.result` prints the error but does not set the process status. Test daemon rejection and unavailable-daemon cases across commands. Keep asynchronous job failure separate from command acceptance; currently consumers must inspect JSON and `last_result`.
3. **C03 — Medium: distinguish configured backend from automatic fallback.** `optimizer list` computes `get_default_optimizer_name(config)` and labels it active, ignoring `config.optimizer`; it also unconditionally lists `local_llm` as available. Test a saved ZhipuAI/local backend while auto fallback would choose another backend, and separate SDK availability from connection/model validation.
4. **C04 — Low: implement or remove the ineffective verbosity option.** `set_verbose` only stores a context flag; no output path consumes it and daemon logging remains INFO. Verify changed logging/output if implemented, or stop promising debug output in help.

Related source documentation was also corrected: `core/importer.py` now documents encoding detection and the newer import arguments; `core/base_llm_optimizer.py` names all three adapters. The root Dockerfile now identifies `PDO_SOCKET_PATH` as legacy discovery configuration. These edits change comments/docstrings only.

## Validation and limits

- `make lint`: passed; Ruff checked source/tests and confirmed 66 formatted Python files.
- `QT_QPA_PLATFORM=offscreen make test`: **340 passed**, **87%** total coverage, on the existing Python 3.13 virtual environment. There were 37 warnings (D-Bus dependency deprecations and an unclosed SQLite test connection). CI itself targets Python 3.12.
- The initial sandboxed test run could not bind local TCP/D-Bus sockets. The full suite passed after running with the required local socket permissions; those initial failures were environmental.
- All **21 CLI help paths** were exercised. Five isolated, mocked behavior probes confirmed ignored custom config on daemon start, zero exit on an error response, JSON bypass of `--watch`, the misleading auto-default listing, and confirmation-free JSON reset. No production batch or provider account was used.
- All 15 Markdown files passed local-link/anchor, balanced-code-fence, and embedded-TOML checks. `git diff --check` passed. The two edited Python modules are AST-identical to the baseline after removing docstrings; application behavior is unchanged.
- Packaged Linux/Windows builds, actual release publication, visible target-system GUI checks, and live AI requests were not performed. No claim of release readiness follows from this audit.
